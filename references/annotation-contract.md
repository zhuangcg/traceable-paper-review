## 原文标注契约

1. 原始 MD 和 PDF 均不可修改。输出两种独立副本和逐支持片段报告，编号与笔记证据一致。先验证 Markdown 摘录，再生成标注；笔记显示每个支持片段的成功、失败或未执行状态。
2. 同一 `claim_type` 映射在两种副本中一致：蓝色背景/理论，绿色数据/方法，橙色结果，紫色讨论/局限，灰色其他。PDF 评论包含编号、论断和解释边界；颜色不代表事实可信程度。
3. Markdown 仅包裹源块内唯一、连续、结构安全的原文；遇到 HTML、公式、跨行、重复、重叠时跳过并报告，不能破坏代码或表格。复制本地图片以保留相对资源。颜色依赖 HTML 支持；标号链接和证据清单可用于纯 Markdown 阅读器。
4. PDF 按 NFKC、大小写及空白规范化词元，其余标点、负号、百分号、比较符和数字必须保留；整份 PDF 只能有一个同页匹配。扫描件、不匹配、跨页、重复和位置无法确认均跳过，不进行模糊猜测。严格匹配可能产生较多漏标。渲染和目视检查所有标注页，核验中文评论；不同版本 PDF 需要另外核对。
5. 不直接写 Zotero 数据库；PDF 含标准 Highlight 与评论，但 Zotero 等软件的导入兼容性需实际测试。原文证据链不因某种阅读器不能渲染颜色而丢失。

依赖准备：用户要求 PDF 处理时，Agent 可在任务级虚拟环境中安装 PyMuPDF，遵循当前权限并告知安装位置。复杂 PDF 建议先用 [MinerU 官方项目](https://github.com/opendatalab/MinerU) 转成 MD；不要把私人文档未经允许提交云端服务。
